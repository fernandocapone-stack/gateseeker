# Project fixtures

Mini projects for the insecure-pattern rules. Generated by a script with a fixed random seed; every credential is synthetic (random characters in a real provider format). `secrets.json` lists them so tests can assert that no full value ever reaches a report.

| Directory | Scenario |
|---|---|
| `vibe-next-supabase/` | Next.js + Supabase project with one or more positive cases for every rule, plus negatives that must not fire: `.env.example` placeholders, a test file holding a secret, a secret inside `node_modules/`, a binary file (`public/blob.dat`) containing a secret-looking token, a server-only service_role reference, an `auth.` schema table, public env vars (`ANON_KEY`, Mapbox `pk.` token, PostHog key). Contains a `package-lock.json` with the real `lodash@4.17.20` vulnerability so combined dependency + pattern runs can be tested. |
| `agent-config/` | AI-agent configuration for GSK-AGENT-001..005: positive, negative and suppressed cases per rule, listed in its README. The inline MCP secret is synthetic and listed in `secrets.json` as `mcp-inline`. |
| `clean-vite/` | Vite + Supabase project following recommended practices. Must produce zero pattern findings, including its safe agent configuration (`.claude/settings.json` with a narrow allowlist, a pinned `.mcp.json` with `${VAR}` secrets, a `CLAUDE.md` that forbids `--no-verify`). Has no `package-lock.json`, so dependency analysis is declared "not analyzed". |

Note for maintainers: the fixture's own `.gitignore` excludes `node_modules/` and `.env.local`; those files were added with `git add -f` and stay tracked.
